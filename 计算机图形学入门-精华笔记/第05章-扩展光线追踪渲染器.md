# 第 5 章：扩展光线追踪渲染器

> 本章不是再加一个光照公式，而是讨论如何把“能跑的教学渲染器”扩展成更灵活、更快、能表示更多物体的渲染器。

## 30 秒掌握本章

五条扩展路线：

```text
相机      → 从固定 O、固定朝向，扩展为任意位置和方向
性能      → 并行、缓存、阴影提前结束、空间结构、子采样
几何      → 从球体扩展到三角形，再到组合实体
材质      → 从不透明扩展到透明和折射
采样      → 从每像素 1 条射线扩展到超采样抗锯齿
```

一句话理解：

> **第 2～4 章解决“如何渲染”，第 5 章解决“如何扩展、加速和提高质量”。**

---

## 1. 任意相机定位

之前的相机有三个限制：

```text
位置固定在 O=(0,0,0)
朝向固定为 +Z
向上方向固定为 +Y
```

取消限制只需要改主循环的两件事：

```text
D_camera = CanvasToViewport(x, y)
D_world  = camera.rotation × D_camera
color    = TraceRay(camera.position, D_world, ...)
```

关键点：

- 相机位置只改变射线原点 `O`。
- 相机朝向只改变射线方向 `D`。
- 光照、求交、阴影和反射算法不需要知道相机如何移动。

可以不用显式写完整旋转矩阵，而是保存三个正交基向量：

```text
right   = 相机屏幕向右
up      = 相机屏幕向上
forward = 相机观察方向

D_world = right*x + up*y + forward*d
```

记忆：

> **移动相机改起点，旋转相机改方向。**

## 2. 性能优化总原则

先测量，再优化。光线追踪很适合优化，但“缓存更多东西”不一定更快，缓存管理本身也有成本。

### 2.1 并行运算

不同像素的主射线彼此独立，场景数据通常只读，因此可以并行：

```text
画布 → 切成多个矩形任务 → 工作线程分别追踪 → 合并 QImage
```

不要为每条射线创建线程。正确做法是固定数量的工作线程配合任务队列，否则线程创建和调度成本会抵消收益。

### 2.2 缓存不变值

球体求交中的：

```text
a = dot(D,D)
b = 2*dot(OC,D)
c = dot(OC,OC) - r*r
```

不同量的有效期不同：

| 值 | 可以缓存多久 |
|---|---|
| `r*r` | 球体半径不变期间 |
| `dot(OC,OC)` | 相机或球体不移动期间 |
| `dot(D,D)` | 当前射线期间 |

注意：阴影射线和反射射线有自己的起点、方向，不能错误复用主射线缓存。

### 2.3 阴影提前结束

阴影只需要知道“有没有遮挡物”，不需要知道最近遮挡物是谁：

```text
AnyIntersection(P, L, ε, tMax)
    找到任意交点 → 立即返回 true
    检查完全部物体 → 返回 false
```

还可以利用**阴影相干性**：相邻像素很可能被同一个物体遮挡，优先检查上一个像素的遮挡物。

### 2.4 空间结构

逐条射线检查所有球体的复杂度会随着物体数量线性增长。可以先检测一个包围体：

```text
射线不碰包围体 → 整组物体全部跳过
射线碰到包围体 → 再检查组内物体
```

多层包围体组成**包围体层次结构 BVH（Bounding Volume Hierarchy）**。它的核心不是改变交点公式，而是尽早排除不可能命中的物体。

### 2.5 子采样

减少主射线数量以换取速度：例如水平和垂直每隔一个像素采样一次，最多减少约 `75%` 的主射线求交。

代价：细小物体可能被漏掉，结果不再严格等价。它属于“主观质量可接受即可”的近似优化。

## 3. 支持其他图元：三角形

渲染器真正依赖的不是“球体”，而是任意图元能提供两个结果：

```text
最近交点 t
交点法线 N
```

因此可以把求交接口抽象成：

```text
Intersection intersect(ray, primitive)
```

三角形求交分两步：

1. 求射线与三角形所在无限平面的交点。
2. 判断交点是否位于三角形内部。

判断内部可以使用：

- 重心坐标（barycentric coordinates）。
- 对三条边分别做叉积方向测试。

若交点在三角形内，法线就是平面法线。光照、阴影、反射代码可以继续复用。

记忆：

> **新增图元只需补“求交点 + 求法线”，不要重写整条渲染管线。**

## 4. 体素构造表示法（CSG）

CSG（Constructive Solid Geometry）用集合运算组合物体：

```text
A ∪ B   并集
A ∩ B   交集
A - B   差集
```

对一条射线，先分别求出它在 `A`、`B` 内部的参数区间，再按集合规则合并区间：

- 并集：在任意一个物体内部。
- 交集：同时在两个物体内部。
- 差集：在 `A` 内部且不在 `B` 内部。

注意差集或交集的边界法线可能需要反向。CSG 的关键是“合并射线区间”，不是先真的生成一个新网格。

## 5. 透明度与折射

### 5.1 透明度

透明物体的颜色由三部分混合：

```text
局部颜色
反射颜色
穿透颜色
```

与第 4 章反射相同，穿透颜色也通过再次调用 `TraceRay` 得到。透明度越高，穿透颜色权重越大。

### 5.2 折射

透明光线不只变淡，还会改变方向。方向由斯涅尔定律决定：

```text
n₁ sinθ₁ = n₂ sinθ₂
```

其中：

- `n₁`：光线当前所在介质的折射率。
- `n₂`：进入的新介质折射率。
- `θ₁`、`θ₂`：光线与法线的夹角。

实现时每条射线必须额外携带当前介质信息，至少需要处理：

- 光线进入物体。
- 光线离开物体。
- 全反射，此时没有折射方向，只能保留反射。

## 6. 超采样：提高边缘质量

每像素一条射线等价于“用像素中心的颜色代表整个像素”，物体边缘会出现锯齿。

超采样在一个像素内发射多条射线并取平均：

```text
pixelColor = average(sampleColor₁, sampleColor₂, ...)
```

常见采样数量：

| 网格 | 射线数 | 理论相对成本 |
|---|---:|---:|
| `1×1` | 1 | 1 倍 |
| `2×2` | 4 | 4 倍 |
| `3×3` | 9 | 9 倍 |
| `4×4` | 16 | 16 倍 |

实用折中是自适应超采样：

```text
先用低采样率
相邻像素命中不同物体或颜色差异大 → 细分
颜色平滑区域 → 保持低采样率
```

子采样追求速度，超采样追求质量；二者方向相反。

## 7. 本项目的 Demo 取舍

### 已实现

本项目在现有第 4 章基础上实现两项第 5 章扩展：

1. **相机预设**：默认、左前方、俯视三个相机位置和朝向。CPU 光线追踪右侧画布与左侧教学场景同步切换。
2. **2×2 超采样**：每个像素发射 4 条略有偏移的射线并平均颜色，用于观察边缘抗锯齿和质量/耗时的权衡。

### 暂不实现

| 内容 | 暂不加入当前 Demo 的原因 |
|---|---|
| 并行任务 | 需要异步渲染和线程安全的图像发布机制，会改变当前教学调用链 |
| 缓存 | 当前场景只有少量球体，缓存收益不明显，容易掩盖基础算法 |
| BVH | 需要重构场景所有权和包围体节点，适合物体数量增大后单独演示 |
| 三角形 | 需要把 `Sphere` 抽象为图元接口，改动面大但可作为下一阶段独立 Demo |
| CSG | 需要区间布尔运算和法线方向处理，适合配合三角形/图元抽象实现 |
| 透明/折射 | 需要介质栈、折射率、全反射和材质混合，属于新的光线传播模型 |

选择标准是：先加入能直接验证第 5 章核心思想、又不破坏现有第 2～4 章教学链路的功能。
